## الخطة الافتراضية: تشغيل مجاني بدون API مدفوع

المشروع يحتوي حالياً على واجهة مجانية لإنشاء قوالب مواقع HTML/CSS/JavaScript ومعاينتها وحفظها في Firestore.

- **قالب فوري مجاني**: يصنع قالباً من الوصف بقواعد برمجية، يعمل على الأجهزة العادية، وليس نموذجاً ذكياً.
- **دردشة وتوليد بالذكاء الاصطناعي داخل المتصفح**: باستخدام [WebLLM](https://github.com/mlc-ai/web-llm) مع نماذج SmolLM2 مفتوحة الأوزان. تحتاج أجهزة الزوار إلى دعم WebGPU وموارد ذاكرة مناسبة وتحميل النموذج أول مرة (مئات الميجابايت أو أكثر).
- **بدون Puter**: لا حساب Puter ولا تكلفة تنتقل إلى المستخدم ولا API Key مزود ذكاء اصطناعي.
- **Firebase**: تسجيل دخول Google وقاعدة Firestore لحفظ مشاريع كل مستخدم.
- **Ollama اختياري لاحقاً**: تبقى ملفات `server/index.js` و`docker-compose.yml` موجودة، لكن الموقع لا يستدعيها في وضعه الافتراضي.

### تنبيه مهم

هذا حل للتجربة بميزانية صفرية من جهة تكلفة استدلال الذكاء الاصطناعي، **وليس ضمان تشغيل مجاني للأبد أو بلا حدود**. Firebase Hosting وFirestore لهما حصص مجانية، وملفات النماذج تُحمَّل من خدمة خارجية وقد تتغير حدودها. بعض المتصفحات لا تدعم WebGPU، كما أن النماذج الصغيرة أقل قدرة من خدمات البرمجة السحابية الكبيرة.

## ما نُفّذ في GitHub
- واجهة React/Vite عربية متجاوبة مع الجوال.
- صفحة «الذكاء الاصطناعي» تستخدم Pages Functions مع Workers AI، ولا تحمّل نموذجاً إلى متصفح الزائر.
- زر «قالب فوري مجاني» لا يستهلك حصة الذكاء الاصطناعي.
- معاينة ملفات الموقع داخل iframe معزول وCSP يمنع الاتصال الشبكي من المعاينة.
- حفظ مشاريع المستخدمين الخاصة في Firestore.
- إعداد مشروع Firebase `zyqmora-ai` دون تضمين Service Account في GitHub.
- ملفات Ollama محفوظة لتشغيل ذاتي مستقبلي اختياري.

## خطوات الاستضافة

### Cloudflare Pages (المستودع الحالي)

المشروع مرتبط بمستودع GitHub `lllbx5ll-crypto/shl` وبفرع `main`. إعدادات البناء المطلوبة:

- Framework preset: Vite
- Build command: `npm run build`
- Build output directory: `dist`
- Root directory: اتركه فارغاً

عند وصول commit جديد إلى `main)، يفترض أن يبدأ Cloudflare Pages عملية نشر تلقائية. تحقق من تبويب Deployments وأن commit المنشور يطابق أحدث commit في GitHub.

### Firebase

1. تأكد من نشر قواعد `firestore.rules` في Firebase Console.
2. تأكد من Google في Authentication > Sign-in method، وأضف نطاق الموقع المنشور في Authorized domains.

لا حاجة لخادم Ollama في النسخة الافتراضية. الاستضافة والنشر عمليتان منفصلتان عن كتابة الكود في GitHub.

## المرحلة المستقبلية

تحسين جودة إنشاء المواقع، محرر ملفات متقدم، قوالب متعددة، نشر مواقع العملاء بعد تأكيد واضح، لوحة إدارة بصلاحيات موثوقة، والاشتراكات. إذا أردنا خدمة قوية تصلح لجميع الأجهزة دون تشغيل نموذج على أجهزة الزوار، فسنحتاج مورداً سحابياً بتكلفة أو حصص استخدام محددة.

## تسليم الموقع للزائر كرابط وليس ملفات

عندما ينشئ المستخدم موقعاً:

1. يراجع الموقع داخل المعاينة الخاصة (لا أحد غيره يراه).
2. بعد رضاه عن التصميم يضغط **«أوافق، انشر الموقع برابط»**.
3. التطبيق يحفظ نسخة منشورة داخل `publishedSites/{uid}_{projectId}` في Firestore.
4. يحصل المستخدم على رابط عام بصيغة `https://YOUR_HOSTING_DOMAIN/s/USER_PROJECT_ID`، يستطيع فتحه أي زائر دون تسجيل دخول.
5. عند تعديل الموقع، تبقى النسخة المنشورة القديمة حتى يوافق صاحب المشروع على تحديثها.
6. يمكن للمالك إيقاف النشر؛ فيصبح الرابط غير متاح.

الرابط يفتح الموقع نفسه داخل إطار معزول يملأ الشاشة، وليس رابط تنزيل ملفات. **تنبيه:** هذه استضافة عبر مسار في موقع ZYQMORA الرئيسي وليست نطاقاً فرعياً مستقلاً لكل مشروع؛ تطوير استضافة المواقع بنطاقات مستقلة يمكن تنفيذه لاحقاً. لعمل الروابط يجب نشر أحدث `firestore.rules` مرة أخرى ونشر واجهة React على Firebase Hosting. Firebase Hosting وحده لا يفعّل الروابط الموجودة في GitHub.

ملاحظة: حذف مشروع خاص لا يلغي تلقائياً نسخته المنشورة على Firestore؛ استخدم زر «إيقاف النشر» أولاً. ترخيص النطاق وتسجيله ونطاق الاستضافة الخارجي قد يكلّف مالاً، لكنه ليس شرطاً لاستخدام نطاق Firebase الافتراضي ضمن حصص الخدمة المجانية.


## Cloudflare Workers AI

يعمل الذكاء الاصطناعي من جهة الخادم عبر Pages Functions وBinding باسم `AI`. لا يحتاج الزائر إلى تنزيل نموذج. الحصة المجانية الحالية لخطة Workers Free هي 10,000 Neurons يومياً، وهي حصة محدودة وليست استخداماً غير محدود.
